# 1.2 Domain Service Contracts

Status: Canonical

Domain services expose narrowly scoped behavior when an immediate response is required. They do not provide unrestricted access to domain persistence.

## Contract principles

- The providing domain owns semantics, validation and lifecycle.
- Callers send intent, not storage mutations.
- Every request is authenticated, authorized, correlated and auditable.
- Material side effects require idempotency keys.
- Sensitive operations fail closed when governance dependencies are unavailable.
- Provider-specific fields are forbidden outside the Provider Integration boundary.
- Synchronous contracts must not become long-running workflow engines.

## Standard request metadata

- `request_id`
- `correlation_id`
- `causation_id`
- `actor_identity`
- `workload_identity`
- `idempotency_key` when applicable
- `policy_context`
- `requested_at`
- `contract_version`

## Standard response metadata

- `decision` or `result`
- `result_version`
- `evidence_refs`
- `policy_decision_refs`
- `audit_ref`
- `completed_at`
- structured error code when unsuccessful

## Canonical services

| Service | Provider | Authorized consumers | Semantics |
|---|---|---|---|
| Policy Evaluation | Policy | All governed domains | Evaluate intended action against exact policy versions |
| Risk Assessment | Risk | Product, Supplier, Approval, Executive Coordination | Produce explainable risk score, factors and constraints |
| Budget Authorization | Budget Governance | Marketing, Runtime, Executive Coordination | Atomically authorize or reject financial consumption |
| Identity Verification | Identity | Approval, Runtime, Audit | Verify human or workload identity and return evidence |
| Product Qualification | Product | Executive Coordination, Approval | Return current qualification state and evidence refs |
| Unit Economics Calculation | Commerce Finance | Product, Budget Governance | Deterministically calculate commercial economics |
| Governed Knowledge Retrieval | Knowledge | Intelligence and authorized domains | Return evidence with provenance, freshness and access metadata |
| Provider Operation | Provider Integration | Runtime only by default | Execute normalized external operation through an adapter |
| Audit Append | Audit | All domains | Append immutable evidence and return an evidence reference |
| Event Publication | Enterprise Events | All registered producers | Publish a versioned event with delivery guarantees |

## Error taxonomy

- `invalid_request`
- `contract_version_unsupported`
- `identity_unverified`
- `authority_denied`
- `policy_denied`
- `budget_denied`
- `risk_threshold_exceeded`
- `conflict`
- `dependency_unavailable`
- `timeout`
- `internal_failure`

Errors must be safe for consumers, while diagnostic detail is retained in observability and audit systems.

## Evolution

Breaking changes require a new major contract version, a published migration path, parallel support during transition and explicit consumer registration. Silent semantic changes are prohibited.
