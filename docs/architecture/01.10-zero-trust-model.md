# 1.10 Zero Trust Operating Model

## Objective

ACOS applies zero trust to every human, service, workload, agent, model, tool, data source, and environment. Network location alone never establishes trust.

## Decision model

Every protected request is evaluated using:

- verified identity
- authentication strength
- device or workload posture
- requested action
- resource sensitivity
- environment
- time and risk context
- policy obligations

## Core components

### Policy Decision Point

Evaluates authorization policy and returns allow, deny, or allow-with-obligations decisions.

### Policy Enforcement Point

Enforces decisions at gateways, services, agent tool boundaries, data stores, and deployment controls.

### Identity providers

Issue identities and claims for users, services, workloads, and agents.

### Security telemetry

Captures decisions, actions, failures, privilege use, data access, and policy violations.

## Access lifecycle

1. Register identity.
2. Verify identity and posture.
3. Evaluate requested access.
4. Apply least-privilege scope.
5. Enforce obligations.
6. Record immutable evidence.
7. Continuously reassess trust.
8. Revoke access when conditions change.

## Privileged access

Privileged access must be approved, time-bound, purpose-bound, strongly authenticated, recorded, and automatically revoked.

## Agent and model controls

- Each agent has an explicit identity.
- Tool access is deny-by-default.
- Tool scopes are limited by capability, tenant, data class, and environment.
- High-impact actions require human approval where policy mandates it.
- Prompt and model input cannot grant new privileges.
- Memory and knowledge access follow the same authorization model as direct data access.

## Environment boundaries

Development, test, staging, and production are separate trust zones. Credentials, secrets, datasets, and privileges are not shared across zones unless an approved control explicitly permits it.

## Exceptions

Exceptions must document ownership, rationale, risk, compensating controls, approval, and expiry. Permanent exceptions are prohibited.

## Continuous verification

Zero trust effectiveness is reviewed through access analytics, policy-denial trends, stale privilege detection, secret rotation coverage, anomalous behavior detection, incident findings, and periodic control testing.
