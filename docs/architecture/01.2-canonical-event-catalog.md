# 1.2 Canonical Event Catalog

Status: Canonical

ACOS enterprise events communicate facts that have already occurred. They are immutable, versioned and owned by the publishing bounded context.

## Event envelope

Every enterprise event must contain:

- `event_id`
- `event_type`
- `event_version`
- `occurred_at`
- `producer_domain`
- `subject_id`
- `correlation_id`
- `causation_id`
- `actor_identity`
- `policy_decision_refs`
- `schema_ref`
- `payload`

Sensitive events additionally require classification, retention and redaction metadata.

## Contract rules

- Event names use `<namespace>.<fact>.v<major>`.
- Released schemas are immutable.
- Breaking changes require a new major version.
- Additive optional fields may remain within a major version.
- Consumers must be idempotent and tolerate duplicate delivery.
- Producers publish through an outbox or equivalent atomic mechanism.
- Consumers record inbox state before applying side effects.
- Events are not commands and may not imply hidden authority.

## Compatibility and retirement

An event version can be retired only after all registered consumers have migrated, replay requirements are satisfied, retention rules are met and an architectural decision record approves retirement.
