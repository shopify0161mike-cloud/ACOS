# 1.2 Anti-Corruption Layer Catalog

Status: Canonical

Anti-corruption layers protect ACOS domain language, authority and data models from external providers. All external provider access is mediated by the Provider Integration domain unless an approved architectural decision defines a stricter boundary.

## Mandatory responsibilities

Every adapter must:

- translate canonical commands into provider-specific requests;
- translate provider responses and webhooks into canonical results or events;
- isolate credentials, SDKs, rate limits and provider identifiers;
- enforce idempotency, retries, timeouts and circuit breaking;
- retain correlation, causation and audit metadata;
- classify failures using canonical error codes;
- prevent provider-specific status values from entering domain contracts;
- support provider replacement without changing domain semantics.

## Adapter catalog

| Adapter family | External systems | Canonical consumers | Required translations |
|---|---|---|---|
| Commerce platform | Storefront and marketplace platforms | Orders, Product, Runtime | Products, orders, refunds, webhooks |
| Payment provider | Payment processors | Orders, Finance projections, Runtime | Authorization, capture, refund, dispute status |
| Supplier provider | Supplier marketplaces and APIs | Supplier | Listings, availability, commercial terms, fulfillment capability |
| Logistics provider | Carriers and third-party logistics | Fulfillment | Shipment creation, tracking, delivery exceptions, returns |
| Advertising provider | Advertising networks | Marketing | Campaign, audience, creative and spend operations |
| Content distribution | Social and publishing platforms | Marketing, Brand projections | Publication, moderation and delivery status |
| Identity provider | Workforce and customer identity systems | Identity | Authentication claims and identity evidence |
| Search and knowledge provider | Search engines, document stores and retrieval systems | Knowledge | Evidence ingestion, retrieval results, source metadata |
| Messaging infrastructure | Queues, streams and notification systems | Enterprise Events | Publish, subscribe, replay and dead-letter operations |

## Security controls

- Credentials are held in approved secret-management systems.
- Workloads receive least-privilege, short-lived access where supported.
- Webhooks require authenticity and replay validation.
- Sensitive payloads are encrypted and redacted from general logs.
- Egress is restricted to registered provider endpoints.
- Provider operations are denied when required policy, identity or budget evidence is absent.

## Failure semantics

Adapters distinguish transient, permanent, throttling, conflict, authentication and policy failures. Retry behavior is bounded and observable. Unknown provider responses fail safely and are quarantined for investigation rather than mapped optimistically.

## Certification

A provider adapter is production-ready only after contract tests, failure-injection tests, idempotency tests, security review, observability coverage, rollback validation and evidence that no provider model leaks into enterprise domain contracts.
